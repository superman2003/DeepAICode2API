# 注册信息持久化修复

控制台原来的进程内入池路径只传递了浏览器指纹名称，漏掉 `MachineID`、
`UserAgent`、`AcceptLanguage`、`SecCHUA` 和 `Platform`。账号持久化后缺少这些字段，
后续请求就会使用进程默认的机器标识和请求头。

修复后，控制台与 CLI 入池都传递完整的注册信息；台账合并也会保留这些字段，
避免阶段更新丢失已记录的信息。

历史数据恢复只匹配同邮箱、同 API Key、同账号 ID 的原始入池台账，
只补空字段，不覆盖已有机器标识，不生成新标识。恢复机器标识时会清理原回退标识下
的配额缓存；后续额度以正常查询的上游响应为准。

回归测试覆盖两条入池路径、状态文件重新打开，以及配额查询和 Anthropic Messages
请求实际发出的机器标识、User-Agent、语言和浏览器提示头。
