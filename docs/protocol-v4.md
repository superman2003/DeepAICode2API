# DeepAI Code 协议 4 兼容修复

2026-11-07 检查原仓库 `2951461586/DeepAICode2API`，最新提交为
`d224a0a5218dc237f205d9133e31e7bfffe525a1`。上游新增了控制台、存储和配额复探优化，
但 `LaneVersion` 仍为 `2`，不能解决本次 HTTP 426。

对照 [DeepAI 官方下载页](https://deepai.org/chat/ai-code) 发布的 Windows x64
0.3.19 客户端，确认其使用 `X-DeepAI-Code-Theos: 4`。
旧协议请求模型目录实际返回 `426 lane_version_unsupported`；协议 4 返回模型目录。

本分支 `v0.2.2` 修复内容：

- 所有上游请求对齐协议 4，使用进程内稳定的随机 `X-DeepAI-Code-Instance`。
- `/theos` 收到 `check_in` 时保留下一次 nonce，按账号、机器和上游地址隔离；
  同一身份的并发刷新串行执行，避免复用旧 nonce。成功和拒绝响应都可携带新 challenge。
- 配额查询发送版本兼容信息、真实进程运行时长与实际调用活动的 beacon。
  无窗口的服务不发送焦点信息；空闲配额刷新不会虚构推理活动。
- 已有 challenge 超过服务器间隔的一半时，在下一次调用前限时刷新。
  刷新失败仍允许模型请求继续，由上游决定是否可调用。
- Chat 请求必须有前导指令消息。已有 system 指令原样保留；首条 developer
  按官方客户端转换为 system；缺省指令时补通用指令。消息、工具、缓存标记和 token 上限保留。
  修复同时覆盖普通 Chat、Claude Messages、Codex Responses 的 Chat 桥接及注册调用探针。
- 移植原仓库 `b0ec437` 的启动修复：先监听，后台刷新模型目录，不再等待外网才开始服务。

本次没有整体覆盖原仓库的存储重构，继续使用现有数据格式和网页更新协议。
服务器 `.env`、账号库、邮箱令牌和网关密钥无需迁移；check-in 只保存在内存，重启后重新取得。

`balance=0` 与协议是否兼容是两件事。实测该余额的账号仍能调用目录中
`theosPerRequest=0` 的免费模型；收费模型是否可用由上游余额和资格决定。
不会把配额 200 响应改成固定余额，也不会把缓存统计伪装成命中。
